# 科研四场景规则

## 共用入口

确认场景、听众、时长、内容材料、模板、输出版本和修改授权。四类场景均为正式支持项，不默认只做开题或项目申报。单位规定优先；以下为可调整的论证骨架，不是固定页数模板。

为每张内容页建立“论点—证据—结论”：论点写具体主张，证据指向已核实材料，结论说明本页如何推进下一页。区分证据来源（本人/文献/示意）与研究状态（已完成/计划/假设）；文献也有实测结果，不能用completed一词自动推定为本人贡献。混合页面分别标清每条主张的归属，整页mixed不能代替逐条说明。

非内容页可不填实验论点；概念、问题或讨论页可无图片证据，但须说明不依赖实证的理由。不得为满足清单而编造数据、引用或实验。

## 开题报告：proposal

目标：证明问题值得研究、方案能回答问题、已有基础足以启动。
推荐链路：背景与意义 → 文献现状 → 具体不足与科学问题 → 目标与研究内容 → 方法及技术路线 → 前期基础 → 进度与风险。
逐项审查：
- 将“已有工作不足”限定在核实的文献与适用条件内，不以少量文献推出整个领域无人研究。
- 将每项研究目标对应到任务、方法、可测指标与预期判据；不给未经依据的定量承诺。
- 将本人前期结果标为前期基础，不能把拟开展的实验作为已完成结果。
- 按用户指定页范围禁用本人图；不把本项目禁令固化成通用前十页禁图规则。
- 为关键可行性假设列验证方法及备选方案。

## 毕业答辩：defense

目标：证明本人完成的工作、结果可信度与贡献边界。
推荐链路：研究问题 → 方法 → 分任务核心结果 → 对照与验证 → 讨论 → 创新贡献 → 局限与结论。
逐项审查：
- 让本人结果成为内容主体，背景篇幅按答辩时长压缩，不套固定比例。
- 将每项创新对应具体方法或结果；文献图只能支持背景/比较，不可冒充本人贡献。
- 保留坐标、单位、实验条件、样本量及误差定义；缺项写明待补，不猜数值。
- 区分相关、因果、可行性演示和统计验证，避免从单次展示推导普适有效。
- 让结论逐条回扣目标，未来工作不计入已完成成果。

## 组会报告：group_meeting

目标：交流新进展、暴露问题、决定下一步行动。
推荐链路：上次目标 → 本阶段实验/分析 → 新数据 → 对照与异常 → 待讨论问题 → 下阶段计划。
逐项审查：
- 保留失败、阴性、重复性不足与异常结果，不为美化而删除。
- 记录样品/批次、实验日期、条件变化与处理方式；避免把不同条件数据无说明拼成一个比较。
- 分开“观察到什么”和“可能原因”，把解释标作假设而非既定机理。
- 为每个待讨论问题给出可选择方案与下一步验证方法，不虚构参会者决定。
- 文献组会作为子类型：研究问题 → 作者方法与证据 → 关键图解读 → 局限 → 对本人研究的启发；不将文献结果写成本周实验进展。

## 项目申报汇报：project_application

目标：说明价值、创新、可行性和实施路径。
推荐链路：立项依据/实际需求 → 核心问题 → 总目标 → 任务分解 → 技术路线 → 前期基础与条件 → 进度/考核 → 风险与替代方案。
逐项审查：
- 对齐申报指南和考核口径；未提供指南时注明，不假定满足某项目要求。
- 将目标、任务、方法、证据基础、预期成果及评价指标逐项对应；避免只有愿景没有验证方法。
- 将预期指标标为目标，不伪装为已达到；预算、团队能力、合作条件只写材料能支持的内容。
- 说明各任务依赖和关键风险；替代方案要能对应具体失败条件。
- 从项目书转PPT时提炼论证而非整段搬运，保留关键限制与假设。申请书正文另走文档工作流。

## 与自适应流程衔接

在本独立技能中，先使用adaptation_gate.py初始化同一份页面/证据计划，并完成逐页适配、授权与代表页记录。research_plan.py仅是基础证据校验模块；只运行它不能绕过适配关卡。最终制作与验收以本包SKILL.md和adaptation-policy.md为准。

## 模板槽位与素材处理

借鉴计划驱动方式，先登记每页用哪个模板页及哪些槽位，而非边改边猜。对所有旧文案、表格单元格、组合内文本和研究图片逐一标记替换/删除/保留；保留必须有理由。未知图片不得因为视觉协调而保留。

科研图优先contain等比完整呈现，或经核对选取完整子图；禁止默认居中裁切。裁切不得丢坐标、比例尺、图例或改变实验含义。局部文字格式、动画、显式背景和页面切换应分别验证，不以形状复制成功证明整页保真。

来源登记必须记录所有派生来源（裁剪、拼图、重绘参考）；禁用规则覆盖全部来源链。生成图显式标“概念示意/计划示意”，不作为实验证据。资料未知时保持未核实，不自动填verified。

## 页面计划使用方法

在技能目录运行（输出始终指定到实际工作区）：

```bash
python scripts/research_plan.py init --scenario proposal --output "工作区/research-plan.json"
python scripts/research_plan.py check "工作区/research-plan.json"
```

场景枚举：proposal=开题、defense=毕业答辩、group_meeting=组会、project_application=项目申报。init不会自动填入通过状态；check退出0仅表示登记规则通过，1表示规则未通过，2表示执行异常。

根字段：schema_version、scenario、template、pages、assets、forbidden_sources。
- template：未使用时null，否则记录source_file绝对路径、read_only=true，可附template_slide与slots对象。源文件仍需单独建立基线，声明只读不是防写保护。
- pages：按page从1连续编号；记录title、role。内容页须填写claim、conclusion、statement_status、evidence_ids、review_note；无素材时填no_evidence_reason。可额外记录template_slide、slots及task_id等供人工执行，当前不自动校验这些扩展字段的映射正确性。
- assets：id、source_type、source_file、locator、caption、citation、verification_status、verification_note、derived_from_sources。locator={slide: 正整数或null, detail: 具体位置说明}；PDF页码与Figure/子图填detail，slide仅指源幻灯片。派生来源数组每项记录source_file和locator，不能只登记裁切后的PNG而丢原始来源。
- source_type：own_result、literature、planned_schematic、generated_schematic、template_identity。示意图额外填label并明确“示意”；文献citation不得为空。
- forbidden_sources：每项source_file、slide_start、slide_end，区间指**输出PPT的页码**，不是来源文件页码。例如1–10表示源文件的任何图片及登记的派生局部都不能用于输出前10页。

登记清单只校验声明：不会自动检测漏报祖先，不识别图像相似度，不验证实验已完成，不检测所有槽位残留，更不保证成品与计划一致。完成素材核验后才能填verified；check成功不能代替原PDF和成品逐页核对。

## 完成判据

1. 场景逻辑：逐页论点与证据匹配，计划/已完成/文献归属清楚。
2. 计划登记：执行research_plan.py check；机器仅核对登记字段和禁用路径，不证明来源真实或科学结论正确。
3. 成品一致性：将实际页码、图片和形状回填计划；人工对照最终PPT，计划通过不证明成品执行了计划。
4. 几何审计：执行audit_deck.py并复核所有warning/skip。
5. 全页视觉：执行SKILL规定的全部页面2倍渲染、四项记录、实际尺度可读性检查及目标软件验证。
6. 交付：提供成品和必要的来源/验收摘要；未完成关键项如实列出，不写全部通过。
